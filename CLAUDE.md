# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Misión Lectura: a Spanish-language reading app for 6-year-olds, self-hosted on a home server (Docker/CasaOS) and used from a tablet on the local network. All UI text, code comments, commit messages and docs are in Spanish; keep that convention.

**Hard constraint: no internet at runtime.** No CDNs, web fonts, or external services. Speech uses the browser's `speechSynthesis` (`client/src/lib/voice.js`), and pictures are emoji, or photos the parents upload for custom words, which are served from the app's own SQLite.

## Commands

```bash
npm run install:all    # install server/ and client/ deps
npm run dev:server     # Fastify API on :8080 (node --watch)
npm run dev:client     # Vite on :5173, proxies /api -> :8080
npm run build          # vite build, then copies client/dist -> server/public
npm start              # run the server (serves server/public if it exists)
docker compose up -d --build   # production-style run; data in volume /data
curl http://localhost:8080/api/health
```

There is no test suite, linter, or type checker. To check a change, run `npm --prefix client run build` and exercise the app in the browser.

The server needs **Node ≥ 22.13** because it uses the built-in `node:sqlite` (`DatabaseSync`). It has no ORM: the schema is `CREATE TABLE IF NOT EXISTS` in `server/src/db.js`, and new columns are added there with `PRAGMA table_info` checks plus `ALTER TABLE` so existing databases still work. The DB lives in `$DATA_DIR/mision-lectura.sqlite` (default `./data/` in dev, `/data` in Docker). CI (`.github/workflows/docker.yml`) only builds and pushes a multi-arch image to `ghcr.io/loky2202/app-lecturs` when you push to `main`.

## Architecture

**The server is thin and the client holds the logic.** `server/src/server.js` is one file: REST routes, prepared statements, and static/SPA fallback. The server does not interpret progress. It stores each profile's whole progress object as an opaque JSON blob (`progress.data`). Separately, it appends task/lesson/mission/story rows to `events`, which `/stats` aggregates for the parent panel. Parent auth works like this: a PIN (default `1234`, stored in `settings`) gives you an in-memory token, sent in the `x-parent-token` header and checked by the `requireParent` preHandler. Tokens are lost when the server restarts.

**Client state** is in `client/src/stores/app.js` (one Pinia store, `useApp`). Its jobs:
- `defaultProgress()` defines the shape of the progress blob. If you add fields, older saved blobs won't have them, so handle missing values.
- `save()` is debounced. `saveNow()` and `flushEvents()` use `fetch` with `keepalive`, and `main.js` calls them on `pagehide`/`visibilitychange`.
- `recordTask` → `finishActivity` → `checkTrophies` handle stars, cards, trophies, daily goal, streak, and level-ups.
- The effective free-play `level` (1–5) is the larger of the auto/manual level and `pathLevel`, which comes from completed units.

**Activity flow.** `views/Lesson.vue` (teach screens, then practice), `views/Play.vue` (free-play missions) and stories all build a list of task objects `{ game, level, world, ...params }`. They pass it to `components/Runner.vue`, which mounts `GAME_COMPONENTS[task.game]` once per task and collects the results.

**Game contract.** Each file in `client/src/games/*.vue`:
- takes a `params` prop (the task object);
- emits `instruction` and `done`;
- calls `useGame(props, emit)` from `lib/game.js`, which provides `level`, `world`, `setInstruction`, `finish(firstTry)`, `good` and `bad`;
- picks words with `pickWord(s)`/`distractors` from `lib/content.js`. These prefer the child's chosen world, relax filters when too few words match, and merge in the parent's custom words from `/api/words`. Custom words can have a photo (`img` URL, stored as a BLOB in SQLite), so render a word's picture with `components/Pic.vue`, not `{{ w.e }}`. Use `picKey(w)` instead of `w.e` to tell pictures apart.

To add a game:
1. Create the component.
2. Register it in `games/index.js` (`GAME_COMPONENTS`).
3. Add an entry to `GAMES` in `content/misc.js` (id, name, emoji, `minLevel`).
4. Optionally, use it in lesson `practice` arrays.

**Content is data in `client/src/content/`:**
- `words.js`: the word bank, built with the `W('PALABRA','PA-LA-BRA','emoji','world')` helper, plus `SYLLABLES`/`VOWELS`.
- `lessons.js`: `UNITS`/`ALL_LESSONS`, generated by helper factories (`vowelLesson`, `consonantLesson`, `reviewLesson`, …). Each lesson has `teach` screens rendered by `components/Teach.vue` and `practice` task lists.
- `stories.js`: stories are added to the lesson path automatically.
- `misc.js`: worlds, trophies, games, breaks, avatars.

Lesson and story IDs are stored in saved progress, so renaming them orphans existing progress.

**Routing** (`client/src/router.js`): Spanish paths (`/camino`, `/leccion/:id`, `/jugar/:game`, `/cuento/:id`, `/padres`, …). A global guard sends the user to `/perfiles` until a profile is selected, except on routes with `meta.noProfile`.
